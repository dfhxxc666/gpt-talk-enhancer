## 3. 本轮已完成并实机通过的修复

### 3.1 Questions 展开性能

问题：打开 Questions 面板时，63+ 行一次显示并立即执行同步几何读取 / `scrollIntoView()`，出现约 1–2 秒卡顿。

当前处理：

- 面板显示前读取 anchor rect；
- 避免打开同一调用栈中的额外 layout read；
- active row follow 改为下一帧执行；
- stale follow 在 close / destroy 时取消；
- 未虚拟化列表；
- 未截断问题文本；
- 原有 viewport 恢复保留。

实机结果：**卡顿明显改善。**

### 3.2 L3 / Fiber 自动研究路线冻结

之前尝试过：

- exact key-join dry run；
- fresh scan；
- `50 / 120 / 250 ms` adaptive rescan；
- mutation-driven event recovery。

实机发现：点击 GPT TalkEnhancer Timeline 后会造成明显主线程卡顿，甚至整个 Codex 变卡。

最终决策：**从正常运行路径冻结该研究线。**

当前保险丝：

```js
const OFFICIAL_NAVIGATION_RUNTIME_ENABLED = false;
const L3_RUNTIME_ENABLED = false;
```

正常产品运行时：

- 不自动做 post-navigation L3 scan；
- 不自动 adaptive rescan；
- 不做 mutation recovery；
- 不自动做 host internal depth probe。

研究代码与测试保留，可按需手动单次执行：

```js
window.__GPTTalkEnhancerV3.runL3ResearchScan()
```

实机结果：**冻结后 Timeline 点击不再造成整机卡顿。**

### 3.3 Codex++ “切换对话保留位置”防回弹兼容

问题：Codex++ 开启“切换对话保留位置”后，GPT TalkEnhancer Work 导航完成会出现底部回弹。

A/B 结果：

- Codex++ 选项开启：回弹；
- 关闭：回弹消失。

修复：

```text
点击 GPT TalkEnhancer Timeline
→ 立即 markPointerIntent
→ 再进入 Local settle / Work navigation
→ verified 后 saveNow
```

即把已有 Codex++ compatibility hook 提前到正确时机，不改变 Work wheel 导航算法。

实机结果：**Codex++ 选项保持开启时，底部回弹消失。**

### 3.4 Work Later 向下加载加速

问题：Work 向下加载明显比向上慢，并有一段一段的卡顿感。

只读定位：

- Earlier 已有专用 Work wheel hydration，默认 cadence 约 `120 ms`；
- Later 原先掉回通用 progressive hydration，`hydrationWaitMs = 900 ms`，并带通用 observer / RAF / motion gate。

修复后：

```text
Local Work + column-reverse

Earlier:
  direction = -1
  专用 wheel hydration

Later:
  direction = +1
  同一 Work wheel 引擎
  距离自适应步长
  接近 tail 自动收敛
```

保留：

- tail endpoint verification；
- post-settle verification；
- Codex++ compatibility；
- Chat fast path 完全不动；
- 非 sidebar Local 仍可回退通用 progressive path。

实机结果：**Work 向下卡顿感消失。**

### 3.5 切换对话前保存最新滚动位置

问题：长 Work 会话实际浏览到 Q63 后，切换对话再回来，可能恢复到旧的 Q54。该问题过去也出现过。

根因：

- GPT TalkEnhancer Timeline 成功导航后会调用 Codex++ `saveNow()`；
- 但用户随后手动滚动到更新位置时，点击左侧其他对话前没有强制写回；
- 因此 Codex++ 可能仍保留较旧位置，例如 Q54。

修复：sidebar click 的 capture phase 中：

```text
当前是 stable sidebar-local thread
且点击目标不是当前 Local thread
→ persistLocalScrollPosition()
→ Codex++ saveNow(current thread, current scroll)
→ 再 invalidate / settle / 切换
```

边界：

- Local A → Local B：保存 A；
- Local A → ChatGPT：保存 A；
- Local A → 再点 Local A：不重复保存；
- 当前不是 stable Local Work：不额外处理；
- 此处不调用 `markPointerIntent`。

实机结果：**Q63 切走再回来保持正常，不再跳回 Q54。**
