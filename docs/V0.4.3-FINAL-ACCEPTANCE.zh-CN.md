# GPT TalkEnhancer 0.4.3 最终验收与发布记录

## 1. 结论

GPT TalkEnhancer 0.4.3 **Navigation UX** 已完成实现、自动测试、Codex++ 安装校验与真实 Codex Desktop 人工验收。

本版本只增加 Navigation 用户反馈层，不修改已冻结的 Navigation 算法核心。

最终状态：**PASS / FROZEN**。

## 2. 版本目标

0.4.3 解决长距离 Qxx 导航过程缺少明确反馈的问题，新增：

- pending target 与 verified active 分离
- 220ms 延迟显示“正在定位 Qxx…”
- supersede-safe UI 状态
- 带 Qxx 编号的失败反馈
- `navigationUx` Debug 状态
- Timeline 顶部首个 marker 的 6px 视觉留白微调

## 3. Navigation UX 状态模型

导航 UI 使用独立状态：

```text
idle
pending
success
failed
```

Debug 可从：

```js
window.__GPTTalkEnhancerDebug.navigationUx
```

读取：

```text
state
target
targetOrder
pendingVisible
```

pending target 不会冒充 ActiveTracker 的 verified active。

## 4. 延迟反馈

点击 Qxx 后立即设置 pending target。

只有导航持续超过 220ms 才显示：

```text
正在定位 Q76…
```

近距离快速导航不会产生短暂 Toast 闪烁。

## 5. Supersede 行为

当旧导航仍在运行时发起新导航：

```text
Q1 pending
→ 点击 Q76
→ Q76 成为唯一当前 pending target
```

旧请求返回 `superseded` 时：

- 不清除新请求的 pending 状态
- 不弹失败 Toast
- 不覆盖新请求的 UX 状态

NavigationAdapter 的既有 supersede 算法未修改。

## 6. 失败反馈

失败提示从通用文案：

```text
未能定位到该消息，请再试一次
```

调整为目标感知文案，例如：

```text
未能定位 Q76，请再试一次
```

成功导航不弹成功 Toast。

## 7. Timeline 视觉收尾

真实 Codex Desktop 验收时发现 Timeline 顶部第一个 marker 过于贴近顶部边界。

最终在 `.gte-rail-markers` 增加：

```css
margin-top: 6px;
```

该调整只影响视觉留白，不改变 marker order、Navigation、ActiveTracker 或 Timeline Cache 语义。

用户实机确认调整后观感明显改善，最终人工验收：**PASS**。
