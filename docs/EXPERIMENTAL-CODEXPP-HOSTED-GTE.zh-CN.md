# 实验性方案：Codex++ 托管 GTE 模块

状态：EXPERIMENTAL / DESIGN REVIEWED / NOT IMPLEMENTED / NOT RUNTIME VERIFIED
日期：2026-09-21
结论：经下列修正后，允许进入隔离原型准备；不是生产架构定案、发布承诺或真实宿主兼容性证明。

选型补充：本文件为候选 A（Codex++ 内部原生模块），不再视为唯一待实验方案。用户随后提供的 Goal Progress 项目展示了候选 B（独立无窗口 Helper + 内嵌页面组件）。见[新增源码评审](EXPERIMENTAL-GOAL-PROGRESS-REVIEW.zh-CN.md)。当前优先准备两者共用的协议/生命周期测试；在 Windows 装载、数据隔离和通信可行性对比完成前，不开始 Codex++ 原生补丁。

最新研究入口：[同类增强项目比较与收敛建议](EXPERIMENTAL-CODEX-ENHANCEMENT-SURVEY.zh-CN.md)。新增项目的 SDK、平台支持和安全边界不能移植成当前 Codex++ 的能力声明。

## 1. 决策与授权范围

用户希望保留官方 Codex 内嵌体验，不采用独立替代客户端。本方案研究：由 Codex++ 原生后台托管 GTE 自有服务，再由其加载最小页面适配层。

当前请求授权审核、将实验性方案同步到项目云端、准备实验。因此本轮仅发布文档、准备隔离源码与检查材料；不安装工具链、不改动产品源码、不运行 launcher/helper/manager，不启用脚本、不连接当前 Codex 调试端口、不重启正在使用的应用。

- 云端目标：本项目独立分支 `codex/gte-hosted-module-experiment`；不合并 main、不打 tag、不发 release。
- 实验文档基线：GTE `6edb4a7b8cc5ee79e7e51ea51543c4434d945ae1`。
- 对照基线：Codex++ v1.3.0，提交 `be6a45852f9992a688f33be933f444ee098fc67a`。
- 用户截图显示 Codex++ 1.3.0 / Codex 26.915.4065.0；这是截图证据，不是本轮进程版本或兼容性检测。
- 旧暂停文档仍约束生产运行时。本轮仅恢复方案研究与实验准备，不代表恢复 Phase 0 实机测试。
- Relay 元数据不随本次文档提交刷新；它记录的是历史 checkpoint，不可据此推断本实验已实现。

## 2. 审核结论与必要修正

| 问题 | 审核判断 | 必须满足的修正/门槛 |
| --- | --- | --- |
| 是否完全不再注入 Codex | 否；最终页面 UI 仍需适配层 | 明示页面注入仍存在，只改变托管与职责归属 |
| 给 Codex++ 管理界面注入 JS 就能获得原生能力吗 | 不能作为成立前提 | 后台原生模块需要源码集成和编译；不逆向补丁管理界面 |
| 是否可直接投放一个第三方原生扩展包 | 本次检查路径未发现通用模块注册/加载契约 | 不假定存在插件 SDK，先按维护小型源码补丁评估成本 |
| 悬浮球能否直接作为插件容器 | 已检查入口和视图只支持固定功能 | GTE 独立挂载与开关，不依赖 Stepwise / Answer Outline |
| 后台托管是否获得全量历史 | 否 | 只保存授权观测和用户自有数据，部分历史明确标识 |
| 原桥接是否足够可靠 | v1.3.0 的页面回调表在重建时重置，包装本身没有请求超时 | 新增有界回调清理、代际隔离、过期响应丢弃；不只加 Promise.race |
| 写入超时是否等于写入失败 | 否，后台可能已提交 | 操作 ID 去重、版本比较和读回；禁止不加判断地重试写入 |
| 独立进程是否天然隔离生产数据 | 否 | 注入测试存储根和伪服务，不读取默认用户配置/数据库；真实进程隔离另验 |
| 是否立即把 JS Core 全部改写成 Rust | 不合理 | 先迁移设置、Prompt 数据和快照存储；索引算法保持可独立测试 |
| 是否影响 v0.6 安全修复和 Work | 不应影响 | 并行实验，不取代原 Safety 工作，不把实验设为发布前置条件 |

结论为“可实验”，不是“没有风险”。当前没有发现必须放弃方向的结构性矛盾；构建、隔离、安全、性能与真实 UI 门槛尚未通过。

## 3. 最小结构

```text
官方 Codex 页面
  GTE UI + 当前可见内容观察 + 用户触发的导航/填入
                  |
  GTE 专用、有界请求协议（由 Codex++ 加载与承载）
                  |
Codex++ launcher/helper 内的 GTE 服务
  自有设置 + Prompt Library + 带来源和版本的索引快照
                  |
  GTE 专用存储（实验仅使用项目内合成数据）
```

管理窗口只负责未来可选的配置入口，不应成为后台运行条件。不是另做一个聊天客户端，也不是建立通用扩展市场。

页面层不得拥有全量会话真相；后台不能凭持久化位置把低置信观察变为权威历史。页面桥接不可用时关闭实验功能并给出有限错误，不干扰官方输入和输出，不自动拉起另一套 GTE。

## 4. 复用范围与需要开发的部分

| 区域 | 可参考/复用 | 需要开发或证明 |
| --- | --- | --- |
| 装载 | `assets.rs` 的编译期 JS 组装、launcher 的加载链 | 独立实验开关、版本握手、挂载/销毁契约 |
| 通信 | `bridge.rs` 的请求应答、连接代际概念 | GTE 命名空间、超时清理、去重、严格数据校验 |
| 服务 | `routes.rs` 的 trait/测试替身模式 | 专用 GTE 服务与有限路由；不得接入既有会话删除/导出等服务 |
| 持久化 | 原子写入实现可作参考 | 独立路径、大小限额、版本冲突、恢复策略与写入串行化 |
| UI | GTE 现有 Timeline / Prompt UI 概念 | 小型适配入口、独立开关、重挂载清理、失效提示 |

不把固定浮球页签硬改成第三方容器；不覆盖它的 `innerHTML`；不依赖外部 monkeypatch。

桥接特别约束：原 `install_bridge` 对同一目标维护连接代际。不得为了 GTE 对同一目标盲目再安装第二套桥接，导致原服务失效。应在单一连接所有者内设计 GTE 专属客户端和响应分发，或经测试证明等效隔离方案；不得直接重用原全局回调表/计数器。若必须改共用桥接，先通过原桥接回归与 GTE 隔离回归，未通过不接真实宿主。

## 5. 最小协议草案（尚非已存在接口）

仅允许实验自有命名空间，例如 `gte/v1/hello`、`gte/v1/document/read`、`gte/v1/document/commit`、`gte/v1/observations/merge`。这些不是 Codex 内部 RPC，不映射到官方会话接口。

- 请求带 `protocolVersion`、`clientInstanceId`、`generation`、`requestId`、操作名及受限 payload。
- hello 返回协议版本、能力和实验状态；不匹配即停止功能，不猜测降级。
- 写入带 `operationId` 与 `expectedRevision`；串行提交，返回持久 revision。
- 相同 operationId + 相同内容返回同一结果；相同 ID 不同内容拒绝。去重记录和数据提交必须保持一致，进程重启后不能重复执行。
- 超时表示结果未知，而非未写入；先读回 revision/操作结果再决定是否重试。
- 页面等待默认上限建议 3 秒、最多 16 个在途请求；作为实验参数而非实测指标。超时/卸载后回调与定时器必须清空。后台执行亦需有界，不能靠前端超时掩盖无限工作。
- 单请求建议上限 256 KiB，存储实验限额 10 MiB；大小与对象深度校验在解析/处理边界落实，不得依赖前端自律。
- document key 只允许服务端枚举值；不接受调用方文件路径、代码、命令、任意 URL。
- 响应明确区分 `ok`、`conflict`、`unsupported`、`invalid`、`unavailable`；不把超时写入谎报成功。

页面共享运行环境不是安全沙箱。命名空间、ID 与握手版本不是鉴权；其它同页脚本可能调用暴露函数。本实验不承诺抵抗恶意同页脚本，只通过最小能力、固定存储根和无敏感数据缩小危害。若产品要求强保密/强隔离，而宿主无法提供可信边界，应停止该路线或重新选架构。

## 6. 索引与导航不变量

- 身份域至少区分 surface / conversation / branch或revision。无法确定身份时只维护临时可见状态，停止持久合并。
- 缓存是存储介质，不是来源；保留原始 observation provenance、观察时间与原身份域。
- `known`、`visible`、`navigable` 分开。未知全局顺序不用伪造 Q1..N；不声明已获得全部历史。
- 同一身份域内，局部 DOM 不可删除既有已知 ID。等数量但不同 ID 的 candidate 也不得覆盖旧集合。
- 重复/乱序 observation 幂等合并；过期 generation 不能更新当前视图或写错会话。
- 修改、分支切换和删除不能靠“只增不减”永远保留旧真相；无可信证据时标为待确认，隔离旧 revision，不做权威替换。
- 无实际导航能力的条目显示不可定位；不为了可点击而后台 sweep。导航仅由用户触发，并且同一时刻只有一个滚动所有者。
- Work 稳定路径不变；实验不得自动接管其 scroll restore、hydration 或 marker fast path。
- Prompt 只允许用户选取后预览/填入，不能自动提交。

## 7. 存储、安全与回退

1. 第一阶段仅合成 Prompt 和合成 Turn，不导入真实对话、缓存、身份、设置或凭据。
2. 测试服务构造器必须显式接收项目内专用数据根；缺省路径、越界路径、符号链接/重解析点逃逸直接拒绝。不要调用会触达真实环境的 Core 默认构造链。
3. 不使用数据库、私有 RPC、React/Fiber、Pagebuster、凭据/token、自动发消息或新增网络拦截。既有 GET conversation 响应克隆例外不在本实验范围。
4. 不调用 Codex++ 已有删除会话、provider 配置、rollout 导出、历史修复、通用脚本执行等路由。
5. 写入先校验后原子替换，使用单写者和 revision；损坏/未知 schema 拒绝覆盖，不自动清库。保留上个已确认版本，恢复必须显式选择。
6. 日志只记录类别、计数、版本和错误码；不记录 Prompt/会话内容或用户路径。数据默认不上传。
7. 实验默认关闭；卸载断开 observer、监听器、定时器、pending 回调并失效异步任务，清理本模块自己的页面节点，不触碰官方节点和滚动状态。
8. 回退是关闭实验并停止使用候选；不是自动覆盖稳定缓存、回滚用户文件或重置生产安装。删除任何本地实验文件仍需遵守用户审批。

## 8. 分阶段实验与验收

### E0：准备（本轮）

- 发布本方案并固定两仓库 SHA；保存独立源码副本，不复制用户安装目录。
- 检查 Git、Node、Rust/MSVC 可用性；不安装依赖或运行下载源码。
- 准备验收矩阵和只读检查入口。缺少工具链明确记录，不能称作构建成功。

### E1：离线契约原型（后续实施）

只做纯服务和伪宿主测试，不运行真实 launcher，不开调试端口，不读取宿主配置。不假定整个上游 `cargo test` 无副作用；先审核实际选中的测试及 build scripts、依赖下载路径，再选择限定目标。

### E2：离线页面生命周期

用合成页面模拟挂载、卸载、DOM 替换和对话切换，验证 UI 不重复、无残留、无隐式滚动和发送。fixture 通过不等于真实宿主通过。

### E3：真实宿主实验（另行明确授权）

先证明实例/数据/端口隔离且不会重启、附着或覆盖当前应用；无法证明则不启动。等待用户安排测试窗口，用专门合成会话验证。版本升级重新核验。

| 验收项 | 场景 | 必须结果 |
| --- | --- | --- |
| 生命周期 | 挂载/卸载各 100 次、重复装载、root 替换 | 每页最多 1 个 GTE 根；卸载后本模块监听、计时和回调为 0 |
| 连接 | 断线、无回应、超时后迟到、旧 generation 回复 | 有界返回；不跨代提交；回调不累积；不影响原桥接 |
| 写入 | 应答丢失后重试、并发 revision、提交中断 | 无重复写；冲突可见；原版本或完整新版本可恢复 |
| 输入 | 超大/深层/非法 schema、非白名单操作、路径逃逸 | 拒绝且不改变数据、不执行任意命令 |
| 索引 | 102→5、同数量替换 ID、重复/乱序、错会话 | 不丢已知 ID、不串会话；不虚构全局顺序 |
| 历史变化 | 编辑、分支切换、不可证明删除 | revision 隔离或待确认，不把旧记录当现行权威数据 |
| 导航/Prompt | 无目标、重复点击、仅选择 Prompt | 不扫全历史、不双重滚动、不自动发送 |
| 性能 | 100 次小请求、200 个合成用户 Turn、1000 次 assistant 文本更新 | 记录环境与 p50/p95；assistant 更新不触发全量索引扫描；记录长任务而非声称“无卡顿” |
| 真实集成 | Codex++原功能 + GTE开关/失联/卸载 | 需 E3 单独证据；不得从离线结果推导 |

建议离线性能目标：小请求 p95 ≤100 ms、一次增量 DOM 工作 p95 ≤8 ms、实验代码归因的 ≥50 ms 长任务为 0。它们是待测目标，不是已达成数字；弱机不达标先定位和缩减范围，不通过放宽数据正确性门槛掩盖。

## 9. 停止条件与替代路线

- 需要禁止的数据源或大量私有宿主状态才能实现基本价值：停止。
- 无法证明与当前实例隔离、无法清理生命周期或破坏原桥接：不进入真实宿主实验。
- Native 模块只增加构建/升级成本，没有减少页面存储与协调职责：不做全量迁移。
- 无完整历史但主要产品价值必须依赖完整历史：单独解决公开数据入口，不让后台托管冒充答案。
- 上游升级频繁造成补丁不可维护：优先提出小型正式扩展点；未经用户授权不向上游发 issue/PR。
- 工具链暂缺：先停在 E0，可继续协议与测试设计；不自动安装软件。

保守备选仍是“现有加载器 + 收缩后的页面适配器 + 纯 JS Core”。它不能改善全部数据边界，但维护成本更低。采用原生后台的条件是 E1/E2 能证明独立持久化、故障隔离和职责减少的实际收益，不以“原生”本身作为理由。
