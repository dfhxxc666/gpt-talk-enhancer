# GPT TalkEnhancer v0.5.2 Navigation Fast-Path Checkpoint

日期：2026-09-10
状态：**FROZEN CHECKPOINT / RELEASE BASELINE / 可后续继续研究**

本文单独保存 v0.5.2 已验证的导航快路径、边界和研究结论。后续继续优化 Navigation 时，应先以本文和 v0.5.2 tag 为基线，不要从已冻结的高成本 Fiber/L3 运行时路线重新起步。

## 1. 目标与原则

当前快路径的目标不是“尽可能少等”，而是：

1. 对已经有可靠证据的 Chat / Work 场景加速；
2. 未满足稳定条件时立即回退既有 progressive / wheel path；
3. 保留真实 geometry、tail、post-settle 与 supersession 验证；
4. 不用高成本内部扫描换取正常点击速度；
5. 不把研究性 Official Navigation / Fiber 逻辑重新接入产品主路径。

## 2. Chat 快路径

### 2.1 Predictive fast path

Chat 的 predictive fast path 只在稳定 ChatGPT conversation identity、长历史索引和已恢复缓存证据足够时启用，并且只服务于远距离 Earlier 导航。

当前设计包含：

- Chat-only 条件，不与 Local Work 共用；
- contiguous / far-Earlier 规划；
- 目标预测后仍执行真实挂载与验证；
- predictive miss 自动回退稳定的 coalesced / progressive 路径；
- moving extent、virtual window 不稳定时拒绝快路径。

对应测试：

```text
Chat predictive fast-path planning is Chat-only, contiguous and far-Earlier
Chat fast-path stability rejects moving extent or virtual window
Chat predictive fast path verifies an unmounted Q1 after one predicted jump
Chat predictive fast miss falls back to the stable coalesced path
```

### 2.2 Coalesced / progressive / boundary

未命中 predictive 时，Chat Earlier 继续使用已经验证的层级：

```text
predictive
→ coalesced（极远且安全）
→ progressive
→ boundary hydration
```

保留：

- 真实 structural progress 才续期；
- stall / inactivity / absolute hard limit；
- Q1 在持续真实进展时允许超过固定 probe 数；
- post-settle verification。

## 3. Guarded mounted fast settle

目标从导航开始就已经 mounted 时，可走 guarded mounted fast settle。

必须保持的条件：

- Turn identity 稳定；
- visible signature 不漂移；
- scroll extent / logical position 不漂移；
- target geometry 在短稳定窗口内不漂移。

通过 hydration 后才出现的 target **不得**借用该快路径，仍走完整 settle / correction。

## 4. Local Work 双向 wheel 快路径

v0.5.2 已将 Local Work 的 Earlier / Later 统一到同一套专用 wheel hydration 引擎，同时保留方向差异。

```text
Earlier: direction = -1
Later:   direction = +1
```

### 4.1 Earlier

- 专用 Work wheel path；
- 约 120ms cadence；
- 距离自适应 step；
- 接近 Earlier boundary 自动缩步；
- delayed DOM update 时继续以真实 progress 判定，不因短暂 stall 过早失败。

### 4.2 Later

v0.5.2 新增 Later 专用 wheel acceleration，取代 sidebar-local Work Later 原先的通用 `hydrationWaitMs = 900ms` progressive 路径。

- 正方向 wheel；
- 与 Earlier 共用已验证 cadence；
- target distance 自适应；
- 接近 physical tail 自动收敛；
- 最后一问继续使用 physical-tail verification；
- 非 sidebar Local 保留通用 progressive fallback。

真实 Codex Desktop 结果：**向下加载卡顿感消失。**

对应测试：

```text
long reverse Work uses monotonic wheel-progressive hydration for earlier history
long forward Work uses wheel-progressive hydration for later history
navigation snaps a known Local tail target to the exact column-reverse boundary
last reverse turn verifies at the physical tail when it is visible but cannot reach the activation line
post-settle verification corrects asynchronous drift before reporting success
```

## 5. Work 快路径必须携带的 Codex++ 兼容层

快路径不能脱离下面两条兼容语义单独修改。

### 5.1 导航前 intent，成功后 save

Codex++ 开启“切换对话保留位置”时，曾出现 Work 导航完成后的底部回弹。

当前顺序固定为：

```text
GPT TalkEnhancer Timeline click
→ markPointerIntent
→ Local restore settle
→ Work wheel/self navigation
→ verified
→ saveNow
```

真实 A/B：该选项开启时回弹已消失。

### 5.2 离开 thread 前保存最新位置

为避免用户手动滚动到新位置后，Codex++ 仍持有旧的 Timeline 导航位置：

```text
点击其他 sidebar thread
→ capture phase 先 saveNow(current thread, current scroll)
→ 再 invalidate / settle / switch
```

同一 Local thread 重复点击不强制保存。

真实结果：曾出现的 `Q63 → 切走 → 回来 Q54` 已消失。

## 6. 高成本 Official Navigation / Fiber 路线冻结

研究阶段确认过稳定状态下可出现 exact key-join：

```text
official markers: 64
known turns: 63
mapped turns: 63
coverage: 1
conflicts: 0
oneToOne: true
```

也确认过宿主重建状态：

```text
official markers: 67
known turns: 63
best coverage: 0.952
conflicts: 3
oneToOne: false
```

曾实现 post-navigation fresh scan、50/120/250ms adaptive rescan 和 mutation-driven recovery，但真实 Codex Desktop 中这些 Fiber/key-join 深扫会造成明显主线程卡顿。

因此 v0.5.2 正式基线固定：

```js
const OFFICIAL_NAVIGATION_RUNTIME_ENABLED = false;
const L3_RUNTIME_ENABLED = false;
```

正常 Timeline 点击：**0 次自动 L3/Fiber 深扫。**

研究实现和测试仍保留。如未来需要取样，只允许手动 one-shot：

```js
window.__GPTTalkEnhancerV3.runL3ResearchScan()
```

未来若继续这条研究线，应优先寻找低成本稳定宿主接口或真正事件证据，不应重新把全量 Fiber traversal 放进正常导航时序。

## 7. 后续可继续研究的方向

优先级建议：

1. 在不改变正确性门禁的前提下继续测量 Chat predictive 命中率；
2. 用真实 trace 比较 Work Earlier / Later 在不同历史长度下的 step/cadence，而不是凭体感继续压等待；
3. 如果宿主出现稳定公开导航接口，再重新评估 Official Navigation bridge；
4. 任何新快路径先独立 synthetic gate，再做真实 Codex A/B；
5. 性能回归时优先关闭新快路径，而不是增加更重的诊断扫描。

## 8. 不可回归清单

后续继续快路径工作时必须保护：

- Chat predictive / coalesced / progressive 分层；
- Work Earlier / Later 专用 wheel path；
- 500ms Local restore settle；
- physical-tail verification；
- post-settle correction；
- navigation supersession；
- Codex++ `markPointerIntent → navigate → saveNow`；
- sidebar pre-switch `saveNow`；
- `OFFICIAL_NAVIGATION_RUNTIME_ENABLED = false`；
- `L3_RUNTIME_ENABLED = false`；
- Questions 展开性能优化。
