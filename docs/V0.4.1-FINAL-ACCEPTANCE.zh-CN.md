# GPT TalkEnhancer 0.4.1 最终验收与冻结记录

## 1. 结论

GPT TalkEnhancer 0.4.1 已完成实现、自动测试、Codex++ 注入验证与真实 Codex Desktop 手动验收，当前结论为 **PASS / FROZEN**。

0.4.1 定位为 **Persistence & Resilience Release**。本版本不扩大产品范围，继续只保留：

1. Conversation Timeline / Question List
2. Prompt Picker / Prompt Library

Browser 产品路线冻结为 reference-only，浏览器端直接使用参考扩展，不继续重复实现 GPT TalkEnhancer Browser 版。

## 2. 相对 0.3 的主要变化

### 2.1 Timeline Index Cache

新增本地缓存：

```text
gpt-talk-enhancer.timeline-cache.v1
```

缓存按 `conversationId` 保存已发现的用户问题索引，仅持久化：

- `id`
- `order`
- `text`
- `shortText`
- `type`
- `lastSeen`

明确不保存：

- Assistant 回复正文
- `visible`
- `source`
- Token / credential / account 信息

边界：最多保留 80 个会话，每个会话最多 1000 条用户问题记录。

同一内容仅 `lastSeen` 变化时不会重复写入 localStorage。

### 2.2 Question Display Normalization

Timeline / Question List 增加纯显示层文本清洗：

- 优先提取 `My request` / `Request` / 中文请求标题后的正文；
- 去除 `Selected text` / `Selection N` 包装标题；
- 清理裸 URL 与 Markdown 链接噪声；
- 大代码块显示为 `[code]`；
- 保留原始 `turn.text`，不修改消息语义或导航索引。

### 2.3 ActiveTracker 激活线边界修复

修复长对话末尾定位正确但 Timeline / Questions 高亮落在前一问的问题。

旧判定把“仍然可见但已完全位于 activation line 上方”的前一条消息误认为 active：

```js
rect.top <= activationLine && rect.bottom > containerRect.top
```

0.4.1 改为只有消息矩形真实跨过 activation line 才优先为 active：

```js
rect.top <= activationLine && rect.bottom > activationLine
```

如果没有消息跨线，则继续选择离 activation line 最近的可见问题。

该修复只影响 ActiveTracker 当前问题选择，不修改 0.3 已验证的远距离 Navigation hydration 算法。

## 3. 真实 Codex Desktop 验收

### 3.1 Timeline Cache 恢复

真实长会话中先通过 Codex 虚拟化窗口渐进发现并缓存问题，然后销毁 GPT TalkEnhancer 内存实例，仅保留 localStorage，再重新 mount。

重新 mount 后观测：

```text
knownTurns         = 36
visibleTurns       = 3
cacheRestoredTurns = 36
cacheTurns         = 36
```

结论：当前 DOM 只渲染 3 条用户消息时，Timeline 可以直接从本地缓存恢复 36 条已知问题索引，**PASS**。

### 3.2 缓存恢复后的远距离 Navigation

使用缓存恢复出的远端问题执行导航：

```text
target       = fallback-turn-36
verified     = true
probes       = 82
settleChecks = 3
```

最终 ActiveTracker 收敛到目标 Q37，结论 **PASS**。

### 3.3 “文档读取规则” Q76 ActiveTracker 修复

真实会话：

```text
conversationId = <redacted-conversation-id>
```

Q76 定位后的真实几何曾为：

```text
activationLine = 202
Q75 bottom     = 196.25
Q76 top        = 202.25
```

旧算法会把 Q75 误判为 active；修复后的算法选择 Q76。

用户随后手动复测确认：

```text
页面实际位置 = Q76
Timeline 高亮 = Q76
Questions 高亮 = Q76
```

结论 **PASS**。

## 6. 安全与架构边界

0.4.1 没有扩大宿主访问范围。继续保持：

- 不使用 `thread/list`；
- 不使用 `thread/read`；
- 不使用 Codex private RPC；
- 不使用 React Fiber；
- 不读取 Codex DB / private IndexedDB；
- 不读取 credential / token；
- 不自动发送 Prompt；
- 不新增轮询式 `setInterval`；
- Conversation Capture 仍只允许精确的当前会话 GET response clone 路径。

## 7. 已知限制

Timeline Cache 只缓存已经被 DOM 或允许的 Capture 路径发现过的问题，不会凭空生成从未加载过的历史问题。

因此首次打开从未探索的长对话时，索引仍需要随着 Codex 自身虚拟化加载逐步建立；后续重新打开已发现部分则可立即恢复。

## 8. 冻结规则

0.4.1 当前状态为 **FROZEN**。

除非发现新的、可复现的 Bug，否则不继续修改：

- Navigation hydration 参数或算法；
- Timeline Cache schema；
- ActiveTracker 激活线逻辑；
- Prompt 核心交互；
- Browser 路线。

后续功能增强进入新的版本规划，不回填到 0.4.1。
