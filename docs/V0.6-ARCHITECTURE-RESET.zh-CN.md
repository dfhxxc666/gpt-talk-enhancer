# GPT TalkEnhancer v0.6 Architecture Reset

状态：DESIGN PROPOSAL / IMPLEMENTATION NOT STARTED
日期：2026-09-20
稳定基线：v0.5.3
前置研究：v0.5.4 Research Closeout

## 1. 为什么要重构

当前问题已经不再只是单个 navigation bug。

v3 当前约：

- 31 个 JS 文件。
- 约 9.3k 行 JS。
- bootstrap.js 单文件约 3.3k 行。
- 多个 MutationObserver / querySelector / hydration / repair / retry 状态机共同参与 Chat Timeline。

最危险的变化是：Host DOM 注入层已经从“观察和增强 UI”逐渐变成“逆向重建宿主完整会话状态”。

这使得以下职责混在同一运行时：

- conversation identity inference
- DOM turn discovery
- order inference
- alias reconciliation
- cache hydration
- history crawl
- true-top bootstrap
- full sweep
- repair
- navigation
- UI
- diagnostics

v0.6 的目标不是继续拆函数，而是重新定义谁有资格拥有哪类状态。

## 2. 官方 Plugin 能力边界

截至 2026-09-20，OpenAI 官方 Plugin 文档公开的主要能力包括：

- Skills
- MCP server
- lifecycle hooks
- optional MCP Apps UI

MCP Apps UI 运行在隔离 iframe，通过 MCP Apps / postMessage JSON-RPC 与宿主通信。

当前公开文档没有提供 GPT TalkEnhancer 所需的下列一等宿主扩展接口：

- 直接枚举当前 Codex/ChatGPT 对话全部 Turn。
- 获取当前宿主完整 conversation tree。
- 注册永久宿主侧边 rail。
- 通过稳定官方 API navigateToTurn(turnId)。
- 直接访问宿主 React/Fiber 内部状态。

因此 v0.6 不采用 Plugin-only 架构。

参考：

- https://developers.openai.com/plugins/concepts/plugins
- https://developers.openai.com/plugins/concepts/mcp-server
- https://developers.openai.com/zh-Hant/plugins/build/chatgpt-ui

## 3. 目标架构：Hybrid，但 Plugin 不在关键路径

    ┌──────────────────────────────┐
    │ GTE Core                    │
    │ domain state / cache /      │
    │ prompts / diagnostics       │
    └──────────────┬───────────────┘
                   │ stable contracts
       ┌───────────┴────────────┐
       │                        │
    ┌──▼────────────────┐   ┌───▼────────────────┐
    │ Thin Host Injector │   │ Optional Plugin    │
    │ DOM + host bridge  │   │ Skill/MCP/Hooks/UI │
    └──┬─────────────────┘   └────────────────────┘
       │
    ┌──▼─────────────────────────┐
    │ Codex / ChatGPT host UI    │
    └────────────────────────────┘

关键决定：

- Core 不知道 DOM。
- Host Injector 不拥有完整会话真相。
- Plugin 不负责 Timeline 正确性。
- Timeline 即使没有 Plugin 也必须正常工作。
- Plugin 只有在确实减少 Host 层职责时才扩大范围。

## 4. Layer A：GTE Core

Core 负责产品自己的确定性状态。

### 4.1 保留

- TurnIndex / TimelineState 的领域概念。
- TimelineCache。
- WorkTimelineCache。
- PromptStore。
- SettingsStore。
- ConversationStore。
- EventBus。
- diagnostics schema。

### 4.2 新硬 invariant：Timeline Knowledge Monotonicity

正常运行时默认只允许：

    5 -> 20 -> 50 -> 102

禁止：

    102 -> 5

任何 destructive replace 必须证明：

- candidate stable IDs 是 existing stable IDs 的超集；或者
- existing 数据已被独立、可信、版本化的数据源明确判定无效。

仅仅满足 candidate 自身 order 连续不够。

建议 API：

- mergeObservation(records)
- markVisible(records)
- mergeTrustedSnapshot(snapshot, proof)
- rejectShrinkingSnapshot(reason)

replaceDomSnapshot() 不再允许作为普通 Chat repair 的通用工具。

### 4.3 数据来源必须带 provenance

每个 Turn 至少区分：

- host-visible-dom
- host-official-marker
- capture
- persisted-cache
- user-triggered-history-load

Core 不根据 DOM 生命周期推断“完整会话已全部发现”。

## 5. Layer B：Thin Host Injector

Host Injector 是 Codex++ userscript/未来其他宿主 adapter 的唯一 DOM 边界。

只保留以下职责：

1. surface / conversation identity observation。
2. 当前可见 user Turn observation。
3. Timeline / Prompt UI mount。
4. 当前 scroll container observation。
5. official marker bridge。
6. 最小必要事件监听。
7. fail-closed compatibility diagnostics。

明确删除职责：

- 自动全量历史 crawl。
- 自动 true-top sweep。
- 自动 destructive Timeline repair。
- 自动用局部 DOM 重建完整会话数据库。
- 自动 Fiber / L3 deep scan。
- 长周期滚动 ownership 竞争。

## 6. DOM Observation 重构

当前 document.body 的 childList + subtree + attributes 全局观察范围过大。

目标：

- 使用两级 observer：极轻量 root-lifecycle observer 只检测 conversation root 替换；scoped conversation observer 只观察真正需要的数据。
- sidebar / composer / conversation 分开 observer。
- root-lifecycle observer 不得触发 full Timeline scan，只负责重新绑定 scoped observer。
- attributes 只监听明确 allowlist。
- streaming assistant 内容变化不得触发完整 Timeline reconcile。
- UI 自己产生的 mutation 必须可过滤。
- refresh 采用 reason aggregation，而不是“一帧一个 full refresh”。

需要建立性能预算：

- 普通 streaming 时不得持续执行全量 visible-turn scan。
- 新 Chat 第一问不得启动 history bootstrap。
- Host adapter 的同步 DOM 读取必须可计时和诊断。

## 7. Chat Timeline 新模型

### 7.1 完整 Timeline 仍是产品目标，但不再承诺后台自动发现全部历史

默认 Timeline 表示：

> GTE 当前已经可信知道的 Turn。

“完整 Timeline”仍然是产品目标；改变的是获取完整性的机制，而不是取消目标。

完整历史加载必须来自：

- 宿主提供的稳定入口；或
- 用户明确触发“加载更早”；或
- 已验证的官方 marker / API。

不能为了让数字看起来完整而后台滚完整个 100Q 会话。

### 7.2 UI 要承认 unknown

如果只知道 24Q：

- 显示 24 个已知问题。
- 可以显示“更早历史尚未加载”。
- 不得把“24”伪装为完整总数。
- 不得为了补总数自动 sweep。

### 7.3 Chat Safety Rules

- known index 不因局部 DOM 消失而缩小。
- repair candidate 小于 existing 时直接拒绝。
- candidate 缺失任何 existing stable ID 时拒绝 destructive replace。
- conversation identity 不稳定时只更新可见状态，不改全局 index。
- repair 最多是 additive recovery，不再是 destructive reconstruction。

## 8. Work Timeline 策略

Work 当前已验证行为冻结。

保留：

- Earlier/Later wheel hydration。
- physical tail/final user turn backtrack。
- post-settle verification。
- Codex++ markPointerIntent -> navigate -> saveNow。
- Work/Chat cache 隔离。
- 当前稳定 scroll ownership。

v0.5.4 研究成果作为候选薄层加入：

    Timeline target
    -> Work NavigationStrategyGate
    -> current official marker query
    -> exactly one canonical marker
    -> HTMLElement.click()
    -> existing verification
    -> failure => v0.5.3 baseline

不得缓存 marker HTMLElement。

## 9. Layer C：Optional Official Plugin

Plugin 只承接官方能力真正擅长的部分。

首批候选：

- Prompt Library 的导入/导出/备份工具。
- diagnostics report 工具。
- 项目/工作流 Skill。
- 可选 hooks，用于 Codex runtime 生命周期诊断。
- MCP 形式的结构化配置/持久数据服务。

暂不迁移：

- Timeline rail。
- active Q 跟随。
- host message click navigation。
- scroll ownership。
- Chat DOM enumeration。

Plugin 是否继续扩大范围，必须由实测证明，而不是架构愿望。

## 11. 实施顺序

### Phase 0：Chat Safety Hotfix

在任何架构搬迁前先止血。

必须完成：

- 禁止 shrinking snapshot 覆盖 existing index。
- 新 Chat 0/1 known Turn 不自动 true-top bootstrap。
- normal Chat auto repair 默认 fail-closed。
- 加入 shrink rejection diagnostics。
- 加入 first-question bootstrap diagnostics。

此阶段不改变 Work。

### Phase 1：Core Contract Extraction

- 定义 TimelineObservation。
- 定义 TimelineKnowledgeStore。
- 定义 HostSurfaceSnapshot。
- 把 Core 单测与 DOM fixture 单测分开。
- bootstrap.js 只通过接口调用 Core。

行为必须等价，除 Phase 0 安全修复外不引入新功能。

### Phase 2：Thin Host Injector

- observer 缩到稳定 root。
- 分离 sidebar / conversation / composer。
- mutation reason aggregation。
- 删除 automatic full sweep。
- 删除 destructive repair orchestration。
- 保留显式 user-triggered Earlier。

### Phase 3：Work OfficialMarkerBridge

仅 Work。

门禁：

- identity stable。
- order health healthy。
- scroll owner idle。
- target canonical marker count == 1。
- no repair/hydration/navigation conflict。

失败立即回 v0.5.3 baseline。

### Phase 4：Plugin Proof of Value

先做小型 PoC，不让 Plugin 进入 Timeline critical path，也不把 Plugin PoC 设为 v0.6 release blocker。

PoC 只验证两个问题：

1. Plugin 是否能稳定承载 Prompt/diagnostics 工具。
2. Plugin 是否能减少 Host Injector 的真实代码职责。

如果不能，Plugin 保持可选，不扩大。

### Phase 5：删除 Legacy Chat State Machine

只有 Phase 0-4 的替代路径验收通过后，才删除：

- Chat true-top auto bootstrap。
- loaded-history automatic sweep。
- destructive DOM repair。
- 相关 retry/freeze/collector 状态。

删除必须分 commit，不进行一次性大爆破。

### Phase 6：恢复产品功能

Timeline Search、Prompt Library v2、诊断 UI 等原 v0.6 Product Features 进入 post-reset backlog。

具体版本号在 Architecture Reset 验收后再决定，不预先锁死。

## 12. 验收矩阵

### Fresh Chat

- 第一问时不得启动 chat-bootstrap owner。
- 不自动调用 hydrateChatEarlierHistory。
- GTE 开启与关闭相比，不出现可感知的数秒冻结。
- streaming 期间 Timeline 不持续 full-rescan。

### Long Chat

- 已知 102Q 时，任何自动 observation/repair 都不得把 index 降到 <102。
- candidate 缺失 existing stable IDs 时必须记录 reject。
- identity 短暂不稳定不得清空持久 index。
- 显式 Earlier 可以增加 known count，但不允许减少。

### Work

- 现有 v0.5.3 Work regression 全通过。
- OfficialMarkerBridge 在已验证矩阵继续保持 wrong target=0。
- fast path 不可用时 baseline 行为无回归。

### Plugin

- 移除/禁用 Plugin 后 Timeline 仍完整可用。
- Plugin failure 不得影响 Host navigation。
- UI iframe 不被视为宿主 sidebar extension。

## 13. Rollback

- v0.5.3 tag 永久作为 stable rollback。
- v0.6 migration 不原地覆盖用户高置信 cache。
- 数据结构升级必须保留旧 cache 或可安全忽略。
- 新 Host adapter / OfficialMarkerBridge 默认可 feature-gate。
- 每个阶段都能独立回退。

## 14. 明确不做

- 不做 Plugin-only 重写。
- 不做 Browser/Web 同步大迁移。
- 不做 Fiber。
- 不做 Pagebuster。
- 不做网络拦截。
- 不做全会话 assistant 全文索引。
- 不在架构重构期间同时开发大量产品功能。

## 15. Complexity Budget

为了防止 Architecture Reset 自身膨胀成第二套大状态机：

- 不允许同时新增两个以上新的 runtime state machine。
- Plugin PoC 不得进入 Timeline correctness path。
- 每个 phase 必须明确说明删除了哪些旧职责。
- legacy Chat state machine 删除量应大于新增 heuristic 量。
- bootstrap.js 变短但总跨层状态变量增加，不算成功。
- Core 不得 import host/codex-desktop。
- Host adapter 不得直接修改 Core 内部集合。
- UI 不得触发 repair。
- Plugin 不得 import Host Injector。

如果某个 phase 只是“移动文件但依赖图不变”，该 phase 视为失败。
