# GPT TalkEnhancer v0.5.4 Fast Path Research 规划

状态：Ready after v0.5.3
定位：Navigation Fast Path Research
前置条件：v0.5.3 已作为新稳定发布基线通过实机验收。
原则：研究可以激进，默认运行时必须保守。

## 1. 研究目标

继续研究 Chat / Work Timeline 导航快路径，目标是降低长对话定位等待时间和无效滚动，但不以牺牲正确性、稳定性或页面流畅度为代价。

v0.5.4 首先是研究版本，不预设所有实验都会进入正式运行时。

## 2. 研究对象

允许研究：

- 已挂载目标的 direct navigation。
- 已知 UUID / stable turn identity 的快速命中。
- 更早历史和更晚历史的低成本边界判断。
- 基于现有 TurnIndex / cache / visible window 的预测性区间缩小。
- Work physical tail 的更快 backtrack。
- Chat loaded-history 已完整时的短路径。
- Official host navigation 能力的只读验证。
- Fiber / L3 / host internals 的 one-shot research probe。

## 3. 默认运行时禁止

以下能力即使保留研究代码，也默认不得自动运行：

- Chat predictive fast path。
- Official Bridge 自动导航。
- React Fiber 自动扫描。
- L3 deep scan 自动扫描。
- DOM mutation 后自动深度研究。
- 普通 Timeline 点击后自动高成本 probe。
- 网络拦截。
- Pagebuster。

研究入口必须显式、一次性、可关闭，并与正式导航路径隔离。

## 3.1 Fast Path 启动硬前置

任何 fast path candidate 在进入实验导航前必须同时满足：

- Timeline order health 为 healthy。
- 当前 cache restore 不是 rejected / pending repair 状态。
- scrollOwnership.owner 为 idle。
- scrollOwnership.conflict 为 false。
- 当前 conversation identity 已稳定。
- 当前没有 bootstrap、repair、manual Earlier 或既有 navigation 正在持有 scroll。

不满足任一条件时直接走 v0.5.3 baseline，不允许为了实验收益绕过 repair 或 ownership 边界。

## 4. 实验框架要求

每一个 fast path candidate 都必须：

1. 有独立 feature flag，默认 false。
2. 能在单次运行中切回 baseline path。
3. 失败时 fail-closed，不改变 Timeline / cache / identity。
4. 不持久化未经正式验证的实验状态。
5. 输出统一 timing / reason / fallback diagnostics。
6. 不修改 Work / Chat 的既有稳定 cache schema。
7. 不允许两个导航控制器同时拥有 scrollTop。

## 5. 性能验收指标

以 v0.5.3 baseline 为对照，不使用单次体感判断。

每个候选场景至少进行多次重复测量，记录 median 与 p95。

进入正式候选至少满足：

- 导航正确率不低于 baseline，实机关键矩阵目标为 100%。
- 不增加 Timeline 洞、identity 错配或 cache 污染。
- 不出现用户可见上下振荡。
- 典型长对话场景 median 导航耗时目标改善至少约 25%。
- p95 不允许出现明显退化；若某场景改善不足，应继续走 baseline。
- 页面主线程不得因自动深扫产生可感知卡顿。
- 快路径失败后 baseline fallback 必须仍可完成定位。

25% 是研究门槛，不是硬编码产品承诺。最终是否合入取决于正确性、稳定性与实机收益共同判断。

## 6. 实机研究矩阵

Chat：

- 当前可见窗口内目标。
- Earlier 方向近距离目标。
- Earlier 方向远距离目标。
- Later 方向目标。
- Pinned Chat。
- Project / 文件夹 Chat。
- 手机创建 Chat。
- bootstrap 已完成与未完成两种状态。
- 首问、中段、最后一问。

Work：

- Earlier。
- Later。
- 最后一问。
- 长 assistant tail。
- Codex++ scroll restore 相关场景。

每个候选都必须与 baseline A/B 对照。

## 7. 研究结果分级

### A：可进入正式候选

正确性不下降，性能收益稳定，fallback 明确，可进入后续正式实现评审。

### B：仅保留研究入口

有价值但成本、兼容性或收益不够稳定。保留 one-shot probe，不挂正常运行时。

### C：冻结

出现明显卡顿、错误导航、跨会话污染、复杂度过高或收益不足。记录 Lessons Learned 后冻结。

## 8. v0.5.4 退出条件

v0.5.4 不要求一定产出正式 fast path。

研究结束时必须得到以下之一：

- 至少一个 A 级候选，形成正式合入规格。
- 或确认当前宿主条件下 baseline 已是更合理选择，并把实验结论冻结。

无论结果如何，v0.5.3 baseline 不得被破坏。

## 9. 向 v0.6.0 的交接

v0.6.0 不等待所有快路径研究成功。

只有 A 级候选才允许进入 v0.6.0 或后续版本的正式运行路径；B/C 级研究不得绑架产品功能开发。
